# 0002: 采用纯前端临时操作员凭证生成（无中心后端依赖）

我们决定在启动终端中采用纯前端（Client-Side）认证与权限分级机制：普通访客输入任意代号与密码即时签发 `LV.3 STANDARD` 临时凭证；若匹配管理员特权凭证，则签发 `LV.5 ROOT` 特权凭证，用于激活管理员专属指令、界面标识与未来特权模块。

## Context

用户要求开屏必须具备输入用户名与密码的登录仪式感，用于创建临时账号并解锁后续指令。但由于站点要求零成本部署于 GitHub Pages（纯静态托管平台），无法搭建中心化认证服务器或关系型数据库。若引入第三方 BaaS（如 Supabase / Firebase），会带来网络依赖、API 密钥暴露风险与部署复杂度。

## Consequences

- 认证过程完全在浏览器沙箱内即时运行，断网或离线亦可秒级登录。
- 用户输入的代号与权限等级会实时注入到终末地 UI 的顶部状态栏与左下角编号中（如 `ROOT OPERATOR // CLEARANCE: LV.5`），增强专属代入感。
- 管理员凭证支持配置化/散列存储，无需后端服务器参与校验。
- 架构保持 100% 静态纯粹性，无需维护后端，满足 GitHub Pages 极简部署诉求。
